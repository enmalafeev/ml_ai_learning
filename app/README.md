# ML Journey

PWA для обучения по плану `ml-plan-aspirantura-1.2.1.md` — вход в ИИ и машинное обучение
для аспирантуры по специальности 1.2.1.

Приложение делает три вещи, ради которых и собиралось:

1. **Даёт материал по теме** — подобранные ссылки на первоисточники плана (хендбук Яндекса,
   MML, 3Blue1Brown, документация NumPy и так далее) плюс чек-лист «что должно остаться в голове».
2. **Отмеряет время на изучение теории** — обратный таймер на плановую длительность темы.
   Пока он не отработает, практика закрыта. Время учитывается по временным меткам, поэтому
   переживает перезагрузку страницы, закрытие вкладки и переход в фон.
3. **Даёт практику и тест** — конкретное задание с шагами и критериями готовности,
   а после него тест с разбором каждого ответа. Порог сдачи — 80%.

## Запуск

```sh
make run              # из корня репозитория: сервер + вкладка в браузере
make run PORT=3000    # другой порт

./serve.sh            # то же вручную: http://localhost:8080
./serve.sh 3000
```

Открой ссылку в браузере. На телефоне — «Добавить на экран «Домой»»: приложение
установится и будет работать офлайн.

Можно открыть `index.html` и двойным кликом, но тогда не будет ни офлайн-режима,
ни установки, а часть браузеров запретит сохранять прогресс. Для реальной учёбы
используй сервер.

Никакой сборки, npm и зависимостей: чистые HTML, CSS и JS.

## Как это работает

Тема проходится в три шага:

```
Теория  →  Практика  →  Тест
таймер     задание       вопросы
чек-лист   с шагами      с разбором
```

- **Практика** открывается, когда таймер теории отработал плановое время.
  Если тема уже знакома — кнопка «Я уже знаю тему» открывает её сразу.
- **Тест** открывается после отметки «практика выполнена». Есть и ручное открытие:
  блокировки здесь — это опора, а не решётка.
- **Тема считается закрытой**, когда пройден чек-лист теории, отмечена практика
  и тест сдан на 80% и выше. Варианты ответов перемешиваются при каждой попытке.

Прогресс, заметки и результаты хранятся в `localStorage` этого браузера.
В «Ещё → Резервная копия» есть выгрузка и загрузка JSON — делай копию раз в месяц,
очистка данных сайта удалит всё.

## Синхронизация между устройствами

Прогресс можно переносить между ноутбуком и телефоном через secret gist на GitHub —
без сервера и аккаунтов. Одна кнопка «Синхронизировать» делает полный цикл: забирает
состояние из гиста, сливает с локальным и отправляет результат обратно.

Настройка:

1. Сделай на GitHub токен: **Settings → Developer settings → Personal access tokens →
   Tokens (classic)**, единственное право — `gist`.
2. «Ещё → Синхронизация между устройствами»: вставь токен, нажми «Синхронизировать».
   Гист создастся сам, его id появится в поле.
3. На втором устройстве введи тот же токен и тот же id гиста и нажми «Синхронизировать».

После настройки в шапке появляется кнопка синхронизации — до ввода токена её нет.

Слияние устроено так, что порядок нажатий не важен и повторный клик ничего не накручивает:

| Что | Как сливается |
|---|---|
| Время теории и практики, результат теста, число попыток | берётся большее |
| Чек-листы, шаги практики, прочитанные статьи, первая неделя | объединяются |
| Практика выполнена, ручные разблокировки | достаточно отметки на одном устройстве |
| Заметки | остаётся более длинная версия |
| Тема оформления, недельная норма, работающий таймер | остаются локальными |

Из-за правила «берётся большее» время не суммируется: если параллельно заниматься
одной темой на двух устройствах, зачтётся большее из двух, а не сумма.

Что стоит понимать до включения:

- Токен лежит в отдельном ключе `localStorage` и **не попадает** в файл резервной копии.
- Право `gist` даёт доступ ко всем гистам аккаунта — сузить его до одного гиста нельзя.
- Secret gist не индексируется, но виден любому, кто знает ссылку.
- `localStorage` привязан к адресу (схема, хост и порт). Открыв приложение по другому
  адресу — скажем, по новому IP ноутбука — увидишь пустой прогресс: он не пропал,
  а остался на прежнем адресе.

## Как обновляется приложение

Самая неочевидная часть проекта: правка файла на диске сама по себе до браузера
не доходит. Вот что между ними стоит.

**Сервер ни при чём.** `serve.sh` — это `python3 -m http.server`, он читает файлы
с диска на каждый запрос. Свежая правка доступна сразу.

**Тормозит service worker.** Он перехватывает все запросы к своему адресу и отдаёт
из кэша `ml-journey-vN`, а в сеть идёт, только если в кэше пусто.

**Обновление запускает смена `CACHE_VERSION`.** При каждом заходе браузер
перезапрашивает ровно один файл — `sw.js` — и всегда в обход кэша. Новый service
worker ставится, если байты изменились, а меняет их только поднятый вручную
`CACHE_VERSION`. Не поднял — браузер считает, что обновлять нечего, и показывает
старую версию сколько угодно долго.

**Что происходит при установке.** Новый service worker скачивает все файлы из
`ASSETS` строго из сети в новый кэш, вызывает `skipWaiting()`, а на активации
удаляет старые кэши и забирает управление открытыми страницами.

**Почему нужны две перезагрузки.** Первая загружает страницу из старого кэша и
параллельно ставит новый service worker — подменить уже исполняющийся JS нельзя.
Вторая собирает страницу из нового кэша. Отсюда ритуал «открыл, закрыл, открыл»
на телефоне.

Отдельная грабля, на которую уже наступали: в `install` файлы запрашиваются
с `cache: 'reload'`. Без этого `addAll` берёт их из HTTP-кэша браузера, и в новый
кэш попадают старые копии — версия меняется, содержимое нет.

## Как добавить тему

Тема — обычный объект в одном из файлов `js/data-*.js`:

```js
{
  id: 'p1-metrics',                  // уникальный, не меняй после начала занятий:
                                     // по нему привязан сохранённый прогресс
  title: 'Метрики качества',
  summary: 'Одна фраза о том, зачем эта тема.',
  theoryMinutes: 150,                // на столько заводится обратный таймер
  practiceMinutes: 120,
  resources: [
    { title: 'Название материала',
      url: 'https://...',            // необязательно: без url будет просто текст
      source: 'домен или «книга»',
      note: 'зачем это читать' }
  ],
  checklist: [                       // «что должно остаться в голове»
    'Понимаю, почему accuracy бесполезна на несбалансированных классах'
  ],
  practice: {
    title: 'Название задания',
    description: 'Контекст: что и где делать.',
    steps: ['Шаг 1', 'Шаг 2'],
    acceptance: ['Как понять, что сделано правильно']
  },
  quiz: [
    { q: 'Текст вопроса',
      options: ['Вариант 1', 'Вариант 2', 'Вариант 3', 'Вариант 4'],
      correct: [0],                  // индексы верных вариантов;
                                     // если их несколько — допиши в текст вопроса
                                     // «(несколько ответов)», приложение это не дорисует
      explain: 'Почему так, и почему остальные варианты неверны.' }
  ]
}
```

Убери `stub: true`, когда тема наполнена — исчезнет пометка «каркас».

После правки файлов подними `CACHE_VERSION` в `sw.js` — иначе браузер продолжит
показывать старую версию, подробности в «Как обновляется приложение».

## Про ссылки

168 ссылок на материалы ведут на первоисточники, названные в плане.
Часть из них проверить автоматически не удалось — хосты `stanford.edu`,
`coursera.org`, `vak.minobrnauki.gov.ru` и `semanticscholar.org` не отвечали
на автоматические запросы. Это не значит, что ссылки битые, но если какая-то
не открылась — ищи материал по названию, оно указано полностью.

Для двух источников ссылка не приводится намеренно: **The Matrix Cookbook**
и **Deep Learning School (МФТИ)** живут на меняющихся зеркалах, и битая ссылка
хуже её отсутствия — они указаны по названию.
