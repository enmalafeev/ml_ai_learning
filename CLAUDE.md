# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

ML Journey — учебное PWA (`app/`) по плану входа в ИИ и ML для аспирантуры по специальности 1.2.1.
Тема проходится в три шага: **теория** (обратный таймер на плановую длительность + чек-лист) →
**практика** (задание с шагами) → **тест** (порог сдачи 80%). Подробное описание предметной
области и формата темы — в `app/README.md`.

Язык проекта — русский: интерфейс, комментарии в коде, тексты данных. Придерживайся этого.

## Запуск и проверка

```sh
app/serve.sh          # http://localhost:8080 (python3 -m http.server)
app/serve.sh 3000     # другой порт
```

Ни сборки, ни npm, ни зависимостей, ни тестов, ни линтера — чистые HTML, CSS, JS.
Проверка изменений — только вручную в браузере.

Открывать через `file://` нельзя: без http не работают service worker, установка PWA, а в
части браузеров и `localStorage` (`app.js` это детектирует и выводит предупреждение в шапке).

## Архитектура

Никаких модулей и бандлера: каждый файл — IIFE со `'use strict'`, экспортирующая один
глобальный объект. Порядок `<script>` в `index.html` = порядок зависимостей, и его нельзя менять:

```
data-phase0.js, data-phase0-math.js, data-phase0-math2.js  →  window.ML_PHASE0_BLOCK_*
data-skeleton.js                                           →  window.ML_PHASE1/2/3, ML_SCIENCE,
                                                              ML_PAPERS, ML_FIRST_WEEK, ML_TIMELINE, ML_RULES
curriculum.js  → window.CURRICULUM   собирает фазы из блоков, строит плоский индекс тем
store.js       → window.Store        сырое состояние в localStorage, логика таймера
progress.js    → window.Progress     вычисляемое состояние: проценты, статусы, блокировки
views.js       → window.Views        чистые функции экран → строка HTML
app.js                               хеш-роутер, делегированные обработчики, тикер таймера
```

Три слоя разделены жёстко: `Views` только читает `Store`/`Progress` и возвращает строку HTML;
`Progress` ничего не пишет; писать в состояние — только через `Store`. `app.js` — единственное
место с обработчиками событий и `location.hash`.

### Данные плана

Иерархия: **фаза** → **блок** (`{ id, title, hint, topics }`) → **тема**. Форма объекта темы и
инструкция «как добавить тему» — в `app/README.md`. В `data-skeleton.js` есть компактный
конструктор `stub(id, title, summary, opts)` для ненаполненных тем; он ставит `stub: true`,
из-за чего в UI показывается пометка «каркас». Убирать флаг — когда тема наполнена.

`curriculum.js` строит `INDEX` (`id → { topic, block, phase, order }`) и `ORDER` (плоский
порядок прохождения). `ORDER` определяет «следующую тему» на дашборде и навигацию
предыдущая/следующая, то есть порядок объявления тем в файлах данных значим.

**`topic.id` — ключ сохранённого прогресса в localStorage.** Переименование id стирает
прогресс пользователя по этой теме. Не менять у тем, которые могли быть начаты.

### Состояние и таймер (`store.js`)

Один ключ localStorage: `ml-journey.v1`. Всё состояние — один JSON: `topics`, `timer`, `papers`,
`firstWeek`, `daily` (секунды по дням `YYYY-MM-DD`), `settings`.

Таймер хранится как `{ topicId, mode, startedAt, running }` — то есть как временная метка, а не
как счётчик. Отсюда три вещи:

- `Store.spent(id, mode)` возвращает зафиксированное время **плюс** незафиксированное время
  работающего таймера. Читать накопленное время надо через него, не из `topics[id].theorySpent`.
- `flushTimer()` переносит накопленное в тему и останавливает таймер; `tickPersist()` переносит
  без остановки (вызывается раз в секунду и на `visibilitychange`/`pagehide`), поэтому прогресс
  переживает перезагрузку, закрытие вкладки и уход в фон.
- Активен всегда не более одного таймера на всё приложение: `startTimer` сначала делает `flush`.

Совместимость со старыми сохранениями держится на двух местах: `load()`/`importJSON()` мержат
разобранный JSON поверх `DEFAULT_STATE`, а `Store.topic(id)` дописывает в запись темы поля,
появившиеся в новых версиях `DEFAULT_TOPIC`. Новое поле состояния добавляй в соответствующий
`DEFAULT_*` — иначе оно не появится у существующих пользователей.

### Вычисляемое состояние (`progress.js`)

`Progress.topicState(id)` — единственный источник всех производных величин по теме: цели и
затраченное время, доли чек-листа и шагов, флаги разблокировки, процент, статус
(`new`/`theory`/`practice`/`quiz`/`done`).

Правила, зашитые здесь: `PASS = 0.8`; практика открывается, когда выработано плановое время
теории **или** стоит `theoryUnlockedManually`; тест — после `practiceDone` **или**
`practiceUnlockedManually`; тема закрыта при пройденном чек-листе + отмеченной практике +
сданном тесте. Вес процента: теория 40%, практика 35%, тест 25%, а без теста — 55/45.
Менять эти правила только здесь, не в `views.js`.

### Роутинг и события (`app.js`)

Хеш-роутинг: `#/`, `#/plan`, `#/phase/<id>`, `#/topic/<id>[/theory|practice|quiz]`, `#/papers`,
`#/stats`, `#/settings`. `parseHash()` разбирает `#/имя/параметры`, `render()` подставляет
строку из `Views` в `#view` целиком.

Обработчики — делегированные на `document` (`click`, `change`, `input`), различаются по
`data-action` и `data-*`-атрибутам (`data-check`, `data-pstep`, `data-q`, `data-paper`,
`data-firstweek`, `data-notes`). Новое взаимодействие — это `data-action` в разметке `Views` и
ветка в соответствующем слушателе; отдельных `addEventListener` на элементы не навешивать.

Так как `render()` заменяет всю разметку, состояние форм теряется. Отсюда два приёма, которые
надо сохранять: `render(true)` рендерит с сохранением скролла, а тикер таймера обновляет цифры
через `textContent` по `[data-timer]`/`[data-mini-timer]` вместо перерисовки.

Сессия теста (перемешанные варианты, выбранные ответы) живёт в `quizSessions` в памяти `app.js`
и не сохраняется — при перезагрузке варианты перемешиваются заново; в `Store` идёт только
лучший результат и число попыток.

## Что легко забыть

- **Любое изменение файлов приложения требует поднять `CACHE_VERSION` в `app/sw.js`** — иначе
  установленное приложение продолжит отдавать старую копию из кэша.
- **Новый или переименованный файл — в три места**: `<script>` в `index.html`, список `ASSETS`
  в `sw.js`, и `CACHE_VERSION` там же.
- В коде нет ни одной стрелочной функции, шаблонной строки или `class` — только `function`,
  конкатенация строк, `const`/`let`. Пиши так же.
- Весь HTML собирается конкатенацией строк: любой текст из данных или ввода пользователя
  пропускай через `Views.esc()`.
- Цвета и размеры — CSS-переменные в `:root` (`css/app.css`), с переопределением для тёмной
  темы через `@media (prefers-color-scheme: dark)` и `[data-theme]`. Хардкод цвета в инлайн-стиле
  допустим только через `var(--...)`.
